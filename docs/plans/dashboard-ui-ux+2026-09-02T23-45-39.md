## 1. Context & Goals

**Current dashboard state** (in `server.js`, a ~150-line inline `dashboardHTML` template literal):
- Two tabs: Live Chat / Intelligence.
- Tailwind via **CDN** + inline `<script>`/`<style>`.
- 10s / 30s `setInterval` polling that re-renders entire lists via `innerHTML` (flicker + XSS-prone).
- **No** overview/analytics, **no** draft-approve UI (the Phase 4 spec asked for "Approve & Send Draft" + a manual reply box — neither exists in code), no reply input, no evaluations list endpoint, and a live-status/connection indicator is missing.

**Goal:** Turn the dashboard into a genuinely useful **multi-page SPA**:
- A real-time **Overview** with stats + charts.
- A working **Chats** console with draft approval + manual reply.
- A **Tasks** triage board and a **Settings** view.
- All served by the same Express server, self-contained, **XSS-safe from the start**.

**Explicit decisions (from user):**
| Question | Decision |
|---|---|
| Structure | **Multi-page SPA-style** (hash router) |
| Charts/visuals | **Chart.js via CDN** (jsdelivr, pinned + SRI) |
| Real-time | **SSE (Server-Sent Events)** — replaces polling |

## 2. Data surface audit (what's available)

Currently in the SQLite schema:
- `contacts: phone_number, name, auto_reply_mode (AUTO/DRAFT/OFF)`
- `messages: id, chat_id, sender, text, timestamp, is_ai`
- `tasks: id, chat_id, task_description, urgency (HIGH/MEDIUM/LOW), status (PENDING/DONE), created_at`
- `evaluations: chat_id, resolution_score (1-10), sentiment, needs_human_help, summary, last_updated`

Current endpoints: `/`, `/api/contacts`, `/api/contacts/:id/messages`, `/api/messages`, `/api/tasks`, `/api/alerts`, `/api/evaluations/:chatId`, `POST /api/contacts/:id/mode`, `POST /api/send-draft`, `POST /api/complete-task`, `POST /api/evaluate`.

**Gaps that block a useful dashboard (must add server-side):**
- No `GET /api/stats` (aggregated overview).
- No `GET /api/evaluations` (list of ALL evaluations — only `:chatId` exists today).
- No `GET /api/drafts` (pending saved drafts).
- No `POST /api/send` (manual reply — today only draft-approve exists).
- No `GET /api/tasks?all=1` (include DONE tasks for completion history).
- No `GET /api/events` (SSE stream).

## 3. New / changed API surface

| Endpoint | Purpose | Backs |
|---|---|---|
| `GET /api/stats` | Aggregated counts + trend arrays | Overview cards + charts |
| `GET /api/evaluations` | List ALL evaluations | Evaluations panel/chart |
| `GET /api/drafts` | Pending saved drafts (`pendingDrafts`) | Draft approve UI |
| `GET /api/tasks?all=1` | Include DONE tasks | Completion history |
| `POST /api/send` | Manual text reply (not only draft-approve) | Reply input box |
| `GET /api/events` | SSE stream: `message`, `draft`, `task`, `eval`, `contact`, `status` | Real-time push |

**`GET /api/stats` response shape:**
```json
{
  "totals": { "contacts": 12, "messages": 340, "aiMessages": 190, "openTasks": 5, "needsHelp": 2 },
  "satisfaction": { "avgScore": 7.2, "byChat": [{ "chat_id": "...", "score": 8 }] },
  "sentimentMix": { "positive": 18, "neutral": 9, "negative": 3 },
  "modeMix": { "AUTO": 8, "DRAFT": 2, "OFF": 2 },
  "volume": [ { "day": "2026-09-01", "messages": 44, "ai": 25 } ],
  "taskCompletion": { "done": 30, "pending": 5 }
}
```

**New prepared statement (better-sqlite3) for volume trend:**
```sql
SELECT date(timestamp) AS d, COUNT(*) AS n, SUM(is_ai) AS ai
FROM messages GROUP BY d ORDER BY d DESC LIMIT 14
```

- Shared **sidebar** + **top live-status bar** persist across routes.
- State (selected contact, filters) in an in-memory store + URL hash where useful.

## 5. Views

### 5.1 Overview (`#/overview`)
- **Stat cards (4):** Active Contacts · Total Messages · Open Tasks · Needs-Human-Help (red when >0).
- **Charts:**
  - Line/bar — **Messages last 14 days** (total vs AI).
  - Donut — **Sentiment mix** (positive/neutral/negative).
  - Donut/bar — **Reply-mode mix** (AUTO/DRAFT/OFF) + **Task status** (done vs pending).
- **Satisfaction panel:** recent `evaluations` (score, sentiment chip, flagged needs-help).
- **Live status strip:** WhatsApp connection + Ollama reachability (SSE `status` event / `/api/stats`).

### 5.2 Chats (`#/chats`) — operations console
- **Left:** contact list with search, mode badge, unread indicator, needs-help highlight.
- **Center:** message thread (bubbles, sender, timestamp, AI vs human), auto-scroll.
- **Top-right of thread:** AUTO/DRAFT/OFF segmented control (persists per contact).
- **Composer (bottom):** manual reply textarea + Send (`POST /api/send`).
- **DRAFT mode:** "pending draft" card with **Approve & Send** / **Discard** (`/api/send-draft`).
- **Drafts drawer:** lists `/api/drafts`.
- **Live:** new messages/tasks push via SSE; typing indicator when Ollama generating.

### 5.3 Tasks (`#/tasks`)
- **Grouped by priority** (HIGH/MEDIUM/LOW) with count badges.
- Checkbox → `POST /api/complete-task`; show completed from `/api/tasks?all=1`.
- Filter: Pending / Done / All; search by text.
- Top alert banner when flagged/needs-help items exist.

### 5.4 Settings (`#/settings`)
- Readonly config (model name, ollama URL, port) — **no secrets**.
- Connection status panel (WhatsApp + Ollama live check).
- Placeholder for future toggles (auto-eval frequency, etc.).

## 6. Real-time (SSE)

- `GET /api/events` opens an SSE stream. Server pushes named events on relevant writes:
  - `insertMessage` → `message` `{chatId}`
  - `insertTask` / `completeTask` → `task`
  - `upsertEvaluation` → `eval`
  - `pendingDrafts.set/delete` → `draft`
  - `upsertContact` / `setContactMode` → `contact`
  - `ready` / `qr` / `disconnected` / Ollama error → `status`
- Client: one `EventSource('/api/events')` (token via query/cookie per security plan). Views re-fetch only the affected slice (diff-aware) → **removes the full-list `innerHTML` flicker and the polling loops**.
- SSE is native (`res.write`). **No new dependencies.**
- ⚠️ EventSource cannot set custom `Authorization` headers — use a short-lived signed token in the query string or a SameSite cookie (per security plan).

## 7. UI/UX design principles

- Dark theme retained (`#0f172a` family) but moved to `dashboard.css` (no Tailwind CDN).
- **Accessibility:** semantic buttons/labels, ARIA on tabs/segmented control, keyboard-navigable contact list, focus states.
- **Empty states:** friendly messages ("No chats yet — scan the QR and start talking").
- **Loading states:** skeletons/spinners on first fetch.
- **Error handling:** toast notifications on failed actions.
- **XSS-safe from the start:** use `esc()` helper / `textContent` on ALL user/AI/DB text (do NOT repeat the current `innerHTML` interpolation bug).
