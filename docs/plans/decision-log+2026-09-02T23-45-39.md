## 2. npm vulnerability work

**Question asked:** "how can you fix the vulnerabilities of npm"

**Findings & resolution:**
- `npm audit` showed 8 vulns (1 low, 1 moderate, 6 high) — nearly all traceable to
  `whatsapp-web.js` → `puppeteer@18.x` → `extract-zip`, `tar-fs`, `ws`, plus `body-parser`/`qs`.
- Ran `npm audit fix`:
  - `whatsapp-web.js` → 1.34.7, `puppeteer` → 24.38.0, `tar-fs` → 3.1.3, `ws` → 8.21.3, `body-parser` → 1.20.6.
- Added `package.json` override `"qs": "^6.16.0"` to clear the 2 moderate `qs` DoS vulns.
- **Remaining (5 HIGH, `extract-zip`):** no safe fix — `@puppeteer/browsers` 3.x is
  Node≥22 + API-incompatible with the pinned `puppeteer-core@24.38.0`. Accepted risk,
  documented. `extract-zip` only runs during browser install, not message handling.

**User note (important):** *"btw ths is locally runned like i do it only in my pc"*
→ Local, single-PC deployment. Lowers severity of network-exposure issues, but
security hygiene still applied.

## 4. WhatsApp login failure — Chrome version mismatch

**User report:** "i tried it and sayed it cant conect to it" (login failed).

**Diagnosis (read-only):**
- `whatsapp-web.js@1.34.7` → `puppeteer@24.38.0` pins Chrome **`146.0.7680.31`**
  (`node_modules/puppeteer-core/lib/cjs/puppeteer/revisions.js`).
- The cache `/home/blue/.cache/puppeteer/chrome/` had been changed by
  `rm -rf .../146.0.7680.31 ...` + `npx puppeteer browsers install chrome@stable`,
  resulting in **v152.0.7977.75** — the **wrong revision**.
- Puppeteer throws `Could not find Chrome (ver. 146.0.7680.31)` → bot can't connect.

**Fix (command given, not yet confirmed run):**
```bash
npx puppeteer browsers install chrome@146.0.7680.31
```
(Or delete the v152 cache; the bot then auto-downloads the pinned 146 build.)
